# 설치 및 검증

새 데스크톱 앱이나 설치 기능을 작업할 때 읽는다. 기존 앱의 일부 수정에는 해당 변경으로 영향받는 항목만 적용한다.

## Windows 통합

- 설치 시 바탕화면 바로가기를 생성한다.
- 메인 창 실행 중 작업표시줄에 표시하고 사용자가 고정할 수 있게 한다. 자동 고정을 강제하지 않는다.
- 실행 중 트레이 아이콘을 표시하며 메뉴에 창 열기와 완전 종료를 제공한다. 창 닫기와 트레이 유지의 동작은 요구사항 및 기존 앱 관례에 맞춘다.
- Windows 설정의 설치된 앱 및 제어판의 프로그램 추가/제거에서 정상적으로 제거할 수 있도록 등록한다.
- 제거 시 앱이 설치한 파일·등록 정보·바로가기를 정리한다. 사용자 문서·프로젝트·업로드·별도 저장 데이터는 임의 삭제하지 않는다.
- 다른 OS를 지정받으면 그 OS의 표준 설치·제거 방식에 맞춘다. Windows UI 항목을 기계적으로 복제하지 않는다.

## 경량 설치기

아래 항목은 경량 온라인 설치기를 제작하는 경우에 적용한다. 사용자가 오프라인 설치 등 다른 방식을 명시하면 해당 방식을 우선하며 온라인 다운로드 흐름을 강제하지 않는다.

- 전체 프로그램을 포함하지 않는 별도 경량 온라인 설치기를 만든다. Windows 기본 결과물은 실제 설치 가능한 설치 실행 파일이며, 포터블 ZIP을 설치기로 대신하지 않는다.
- 기본 다운로드 원본은 프로그램의 GitHub 공개 릴리스다. 다른 배포 대상이나 비공개 배포가 지정되면 해당 인증·접근 방식을 사용한다. 운영자 토큰을 설치기에 내장하지 않는다.
- 실행 시 최신 정식 릴리스를 확인하고 대상 OS·아키텍처에 맞는 패키지를 선택한다. 초안·시험판을 정식 버전으로 취급하지 않는다.
- 패키지의 특정 버전 URL을 고정하지 않는다. 같은 설치기로 이후 최신 정식 버전도 설치되어야 한다. 지원 패키지가 없으면 임의의 다른 플랫폼 파일을 설치하지 말고 명확히 알린다.
- 다운로드·설치 진행 상태와 실패 원인·재시도 방법을 표시하되 인증정보를 로그에 남기지 않는다.
- 신뢰할 수 있는 배포 원본에서 내려받고 크기·무결성 등 배포 방식에 맞는 검증을 완료한 뒤 실행한다. 검증 실패 시 설치를 진행하거나 완료로 표시하지 않는다.
- 배포 자산 이름과 매니페스트 구조는 설치기가 안정적으로 찾을 수 있도록 유지한다. 날짜 접두사로 참조를 깨뜨리지 않는다.
- 공개 배포가 아직 요청되지 않았다면 로컬 테스트용 원본이나 격리된 테스트로 흐름을 검증하고 실제 공개 원본 검증은 미완료로 보고한다. 설치기를 테스트하려는 이유만으로 공개 배포하지 않는다.

## 검증 범위

- 새 앱 또는 설치 경로 변경: 깨끗한 테스트 환경에서 설치 → 실행 → 바로가기·작업표시줄·트레이 → 완전 종료 → 제거를 확인한다. 사용자 데이터 보존도 확인한다.
- 온라인 설치기: 최신 정식 버전 선택, 정상 다운로드·설치, 다운로드 또는 검증 실패 시 설치 차단을 확인한다. 빌드 성공만으로 대체하지 않는다.
- 기존 앱 일부 수정: 변경 기능과 영향받는 경로를 검증한다. 관련 없는 설치·제거를 반복하지 않는다.
- 격리된 환경이나 임시 경로를 우선한다. 사용 중인 설치본·사용자 데이터를 덮어쓰거나 제거해야 한다면 먼저 확인한다.
- 환경상 불가능한 항목은 미검증으로 남기고 이유를 보고한다. 증거 없는 성공 주장이나 시험을 위한 요청 밖 시스템 변경을 하지 않는다.
