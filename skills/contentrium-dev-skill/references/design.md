# 화면 디자인

데스크톱 앱의 신규 화면 또는 요청된 UI 디자인 범위에만 적용한다. 기존 화면의 부분 수정은 기존 디자인을 유지하고 변경된 요소만 검증한다. 스킬·플러그인 소개에는 배포 문서의 첫 페이지 기준을 사용한다. 사용자가 별도 디자인을 지정하면 그 요구를 우선한다.

## 시각적 기준

새 설치·시작 화면의 기본 디자인은 승인된 콘텐츠리움 편집실 시안을 참고한다. 해당 화면을 새로 제작하거나 전면 개편할 때 다음 이미지를 확인하고, 구현 방식이 필요하면 HTML/CSS 원본을 읽는다. 부분 수정에 시안 확인·테마 교체·배경 재생성을 강제하지 않는다.

이 시안은 실제 폰트와 UI 위에 글자 없는 생성 배경을 조합한 예시다. 공유할 기준은 레이아웃·분위기·타이포그래피·진행 표시이며, 앱 이름·문구·배경 소재는 대상 프로그램에 맞게 바꾼다. 영상 편집용 배경과 생성 프롬프트는 예시 전용이다. 새 배경이 필요한 다른 프로그램에는 기능에 맞는 배경을 생성한다. 기존 앱의 승인된 배경은 관련 없는 수정 때문에 교체하지 않는다. 같은 프로그램의 설치·시작 화면은 일관성을 위해 같은 배경을 공유할 수 있다.

시연 코드의 68% 진행률과 상태 전환은 디자인 확인용이다. 실제 앱에는 복제하지 않고 설치·초기화 상태에 연결한다. HTML 예시는 특정 앱 프레임워크 사용을 강제하지 않는다.

최초 사용자 제공 [참고 이미지](design-reference.png)는 보조적인 분위기·구도 자료다. 승인된 시안과 다르면 승인 시안을 우선하며, 스크린샷 자체를 배경으로 사용하거나 주변 다른 창의 UI를 재현하지 않는다.

- 검정·차콜 중심의 무채색, 부드러운 빛과 그림자, 절제된 대비로 차분하고 시네마틱한 인상을 만든다.
- 설치·시작 화면은 왼쪽 상단의 큰 앱 이름, 그 아래 브랜드 영역, 중앙에서 오른쪽으로 깊이감 있는 배경 이미지, 하단의 상태 문구와 얇은 진행 표시를 기본 구도로 삼는다.
- 배경에는 겹쳐진 패널·프레임 같은 원근감을 활용할 수 있다. 산 풍경, 패널 수, `Frame Fixer`라는 이름은 특정 참고 예시이며 모든 앱에 복제하지 않는다. 앱의 실제 이름과 용도에 맞춘다.
- 공통화하는 것은 화면 구성·무채색 분위기·타이포그래피 원칙이다. 배경 이미지의 소재와 구도는 프로그램의 핵심 기능을 표현하도록 개별 설계하며, 같은 산·패널 이미지를 모든 앱에 재사용하거나 똑같이 생성하지 않는다.
- 배경 제작 전에 프로그램 이름과 핵심 기능을 기존 자료에서 확인한다. 확인되지 않으면 사용자에게 묻는다. 영상 편집기는 클립·편집 레이어·필름의 흐름 등 편집 기능을 표현하고, 다른 유형의 앱에는 해당 기능에 맞는 소재를 선택한다.
- 신규 메인 작업 화면은 앱의 브랜드·사용성을 기준으로 색감·타이포그래피·간격을 정한다. 설치·시작 화면의 무채색 테마를 기존 작업 화면에 강제하지 않으며, 도구, 입력, 결과, 오류 상태가 명확하게 읽혀야 한다. 전체 화면에 장식 이미지를 깔아 작업 영역을 방해하지 않는다.

## 이미지와 실제 UI 분리

- AI 이미지 생성은 배경 일러스트레이션에만 사용한다. 앱 이름, 브랜드 글자, 설명, 상태, 진행률, 버튼, 진행 바, 창 제어는 생성 이미지에 넣지 않는다.
- 모든 텍스트는 실제 폰트로 구현하고 모든 조작 요소와 진행 표시는 실제 UI 컴포넌트로 구현한다. 한글 지원과 사용·배포 가능한 폰트를 선택하고 필요한 라이선스 고지는 유지한다.
- 브랜드 글자도 폰트로 렌더링한다. 참고 이미지의 로고를 잘라 붙이거나 비슷한 글자를 생성하지 않는다. 사용자가 공식 로고 파일 사용을 별도로 요청한 경우에만 제공된 자산을 사용한다.
- 배경 생성 시 텍스트·로고·워터마크·UI 없는 이미지를 요청하고, 왼쪽 제목과 하단 상태 영역에 어두운 여백을 확보한다. 정확한 앱 이름·폰트·상태 문구는 코드에서 별도로 배치한다.
- 실제 배경 제작이 필요한 시점에 이용 가능한 이미지 생성 도구와 해당 지침을 사용한다. 규칙을 읽었다는 이유만으로 새 이미지를 생성하지 않는다. 생성 도구가 없으면 제한을 알리고 생성 완료로 주장하지 않는다.
- 생성된 배경은 프로젝트의 정적 자산으로 포함한다. 설치 중이나 앱 시작 때 이미지 생성 서비스에 접속하게 만들지 않는다. 설치기가 경량으로 유지되도록 크기와 해상도를 최적화한다.

## 해상도·배율·다중 모니터 대응

신규 데스크톱 앱과 설치 UI, 또는 요청된 표시 오류 수정에 적용한다. 기존 앱의 관련 없는 기능 수정에 전체 UI 재설계를 강제하지 않는다. 스킬·플러그인의 README 디자인에는 데스크톱 DPI 기준을 적용하지 않는다. 부분 수정에서는 영향받는 화면과 표시 경로만 검증하며, 앱 본체만 수정한 경우 관련 없는 설치기 검증을 강제하지 않는다. 다른 OS는 해당 OS와 UI 도구의 배율 방식에 맞춰 적용한다.

- 승인된 시안의 분위기와 정보 위계는 유지하되, 고정 크기·좌표·화면 비율을 그대로 복제하지 않는다. 작은 논리 작업 영역에서는 가독성과 필수 동작 접근성을 우선해 배치·여백·패널을 조정한다. 포함된 HTML 시안은 디자인 참고이며 모든 DPI 환경을 검증한 제품 구현이 아니다.
- 물리 해상도와 OS 배율을 구분한다. 4K라는 이유만으로 사용 가능한 UI 공간이 넓다고 가정하지 않고, 현재 모니터의 논리 좌표와 작업 영역을 기준으로 레이아웃을 계산한다. 작업표시줄·창 테두리도 고려한다.
- 선택한 UI 프레임워크의 공식 DPI·자동 배율 처리 방식을 우선 사용한다. 프레임워크가 이미 적용한 배율을 수동 계산이나 화면 전체 확대 변환으로 다시 적용하지 않는다. 특정 해상도에 맞춘 절대 픽셀 위치·크기로 전체 UI를 고정하지 않는다.
- 설치기, 시작 화면, 메인 창, 설정·오류·파일 선택 등 앱이 소유한 보조 창에 일관되게 적용한다. 설치기는 앱 본체와 별도 실행 경로로 검증한다. OS가 소유한 보안 승인창·시스템 대화상자의 외형을 임의 변경하지 않는다.
- 창의 최초 크기·최소 크기는 실제 작업 영역 안에 들어가도록 정한다. 공간이 부족하면 여백과 패널을 조정하고 필요한 영역에 스크롤을 제공한다. 읽을 수 없을 정도로 글자와 버튼을 일괄 축소하지 않으며, 설치·취소·확인·닫기 등 필수 동작에 접근할 수 있게 한다.
- 텍스트는 실제 폰트로 렌더링하고, 글자 크기 변경·긴 한글 문구에 맞춰 줄바꿈과 컨트롤 높이를 조정한다. OS 텍스트 크기 설정은 디스플레이 배율과 별도 항목으로 확인한다. 배경·로고·미리보기는 종횡비를 유지하며 가로·세로를 따로 늘리지 않는다. 장식 배경은 의도된 크롭을 허용하되 로고·문서·영상 등 의미 있는 내용은 기본적으로 전체가 보이도록 맞추고 여백을 둔다. 사용자가 선택한 확대·크롭 기능은 별도로 유지한다. 확대 시 흐려지지 않도록 용도에 맞는 벡터 또는 충분한 해상도의 자산을 사용한다.
- 배율이 다른 모니터로 창을 옮기거나 해상도·배율·모니터 연결 상태가 바뀌면 해당 환경에 맞춰 레이아웃과 그리기 영역을 갱신한다. 창 위치를 복원할 때는 현재 연결된 화면의 작업 영역으로 제한하여 창이 화면 밖에 숨지 않게 한다.
- 캔버스·영상·이미지 미리보기와 드래그 핸들은 논리 좌표와 실제 그리기 해상도를 구분해 표시 위치와 클릭·드래그 좌표가 일치하도록 한다. UI 배율 때문에 저장·내보내기 결과물의 원래 픽셀 크기가 바뀌지 않게 한다.
- 사용자의 해상도·배율을 낮추거나 시스템 DPI 설정·호환성 옵션을 강제로 바꾸는 것을 해결책으로 삼지 않는다. 실제 구현 방법은 선택한 UI·설치 도구에 맞추며 Rust 기본값 때문에 UI 도구를 교체하지 않는다.

### 표시 검증

- 사용자가 문제를 보고한 실제 해상도·OS 배율·텍스트 크기·모니터 구성을 최우선 재현 조건으로 기록한다. 조건이 확인되지 않으면 확인 가능한 범위를 검사하고 해당 환경 재현 여부를 명확히 보고한다.
- 신규 Windows UI의 대표 검증 조합은 1920×1080/100%, 2560×1440/150%, 3840×2160/150%·200%·250%다. 모든 해상도와 배율의 전체 조합을 강제하지 않으며, 사용자 환경이 125%·175%·300% 등 다른 값이면 해당 조건을 추가하거나 우선한다. 지원 최소 작업 영역도 확인하고 지원 범위를 명시한다.
- 초기 표시, 창 축소·확대, 긴 문구, 진행·실패·재시도·완료 상태에서 찌그러짐·잘림·겹침·흐림·버튼 접근 불가·클릭 좌표 어긋남을 확인한다. 신규 앱은 설치기와 앱을 각각 시작하고, 부분 수정은 영향받는 실행 경로에서 확인한다.  배율이 다른 두 모니터 사이 이동 및 모니터 분리 후 재실행도 가능한 환경에서 확인한다.
- 브라우저 창 크기나 확대율 변경만으로 실제 Windows DPI·다중 모니터 검증을 완료했다고 판단하지 않는다. 실제 앱·설치기의 렌더링과 조작 결과를 확인한다. 장비·환경이 없어 수행하지 못한 조합은 미검증으로 남기고, 사용자 디스플레이 설정은 임의 변경하지 않는다.

## 화면 동작과 확인

- 상태 문구는 시스템 점검·다운로드·검증·설치·완료 등 실제 처리 단계와 연결한다. 측정 가능한 진행률은 실제 수치를 쓰고, 측정할 수 없는 단계는 불확정 진행 표시를 사용한다.
- 신규 앱에는 실행 요청을 받았음을 즉시 알 수 있는 표시가 반드시 있어야 한다. 초기화가 필요한 앱은 시작 화면과 실제 준비 상태를 표시하고, 즉시 열리는 앱은 메인 창의 즉각적인 표시로 실행 시작을 알린다. 사용자가 시작 화면을 명시적으로 요청한 경우 해당 화면을 구현하되 표시를 위해 인위적으로 시간을 지연하지 않는다.
- 작은 창, 고해상도 배율, 긴 앱 이름과 한글 문구에서 잘림·겹침·흐림을 확인한다. 배경 크롭이 달라져도 실제 텍스트와 컨트롤은 안전한 영역에 남아야 한다.
- 정상 진행뿐 아니라 실패·재시도·완료 상태도 가독성과 동작을 확인한다. 실제 렌더링 화면에서 텍스트가 배경 이미지에 합쳐져 있지 않고 UI로 구현되었는지 검증한다.
