# GitHub 소개 및 배포

데스크톱 앱·스킬·플러그인의 GitHub 소개·README 작성 또는 배포·릴리스 작업에서 관련 항목만 읽는다. 소개·도구·공개 범위·보안·릴리스 관리는 공통이며, 세 가지 배포 구성과 설치기 검증은 데스크톱 앱 전용이다. 스킬·플러그인은 플랫폼 고유 설치 명령·패키지·등록 방식을 유지한다. README 작성 요청은 외부 공개나 릴리스 변경의 승인이 아니다.

## 대상과 공개 범위

- 데스크톱 앱 배포의 기본 대상은 GitHub 공개 저장소다. 사용자가 지정한 비공개·다른 배포 대상이 우선한다.
- 기존 비공개 저장소의 공개 전환은 명시적으로 요청받거나 승인받은 경우에만 한다.
- 설치파일 공개와 소스 전체 공개를 구분한다. 배포 요청만으로 작업 폴더·소스·개발 이력을 전부 올리지 않는다. 공개 범위가 불명확하면 배포에 필요한 파일만 공개한다. 기존 공개 프로젝트의 방침과 필요한 라이선스 의무는 유지한다.
- 새 메인 저장소는 프로그램 고유 이름을 사용하고 금지 문자만 최소 조정한다. 배포 표시용 `-release`, `-릴리즈`, `-버전`, `-v2` 등을 덧붙이지 않는다. 고유 이름 자체의 표현은 유지한다.
- 기존 저장소를 이름 규칙에 맞추려고 임의 개명하거나 대체하지 않는다. 릴리스 태그·프로그램 버전은 정상적으로 관리한다.

## GitHub 작업 방식

- GitHub 플러그인이 제공되는 환경에서는 현재 플러그인 지침을 확인하고 연결 도구를 우선 사용한다. 지침에서 안내하는 GitHub CLI 등 보완 도구는 요청된 작업 범위에서 별도 승인 없이 사용한다.
- CLI 보완을 금지된 우회로 취급하지 않는다. 플러그인 지침에 명시된 웹 절차도 별도 승인을 반복 요구하지 않는다.
- GitHub 플러그인 지침에 없는 계정 웹 접근이 불가피한 경우에는 사유·작업 범위를 설명하고 허락을 받은 후 진행한다. 사용자 지침이 Aside를 지정했다면 Aside를 사용하며 금지된 브라우저로 대체하지 않는다.
- GitHub 플러그인이 제공되지 않는 에이전트에서는 해당 환경에서 허용된 GitHub 연결 도구 또는 인증된 GitHub CLI를 사용한다. 플러그인 전용 등 사용자의 명시적인 제한이 있으면 이 대체 규칙으로 우회하지 않는다. 브라우저 도구 역시 호스트와 사용자 지침을 따른다.
- 실제 확인한 지침만 근거로 삼는다. 도구 사용 허용이 저장소 삭제·권한 확대·요청 밖 공개 등의 승인으로 확대되지 않게 한다.
- 도구가 지원하지 않거나 접근이 막히면 구체적인 제한과 남은 작업을 보고한다. 같은 실패를 무한 반복하거나 임의의 다른 계정으로 전환하지 않는다.

## 사용자용 첫 화면

### 고정 README 형식

- 새 README 제작·전면 개편에는 [고정 템플릿](readme-template.md)을 복사해 사용한다. Contentrium Dev Skill 첫 페이지의 형식을 기준으로 **전폭 커버 → 중앙 제목·짧은 소개 → 중앙 배지 줄 → 중앙 바로가기 → 구분선 → 빠른 설치 → 3열 핵심 기능 표 → 큰 기능 시각 자료와 접는 추가 예시 → 유형별 설치·배포 안내 → 사용 예시 → 적용 범위·제약 → 접는 상세 안내·영문 소개 → 하단 브랜드·라이선스 → 홈페이지 버튼** 순서와 표시 형식을 유지한다.
- 프로젝트별로 바꾸는 것은 이름·문구·커버 소재와 색상·기능·실제 예시·설치 명령·링크다. 커버·버튼·표·시각 자료를 일반 텍스트 목록으로 대체하거나 생략하지 않는다. 해당 없는 세부 항목은 같은 영역 안에서 그 프로젝트의 실제 정보로 바꾼다. 데스크톱 앱의 세 배포물을 스킬에 강제하지 않는다.
- 배지는 확인 가능한 정보만 사용한다. 스크린샷이 없는 프로젝트의 큰 시각 자료는 실제 기능을 설명하는 SVG 도식으로 만든다. 추가 화면 대신 추가 사용 예시를 접는 영역에 넣을 수 있다. 템플릿의 중괄호 자리표시자와 주석은 공개 전에 실제 내용으로 교체·제거한다.
- 기존 디자인을 유지하는 부분 수정이나 사용자가 명시한 다른 형식이 있으면 그 범위를 우선한다. 단순 재배포를 이유로 새 형식을 소급 적용하지 않는다.

### 시각적 완성 기준

- 이 절은 앱·스킬·플러그인의 README 신규 제작·전면 개편에 동일하게 적용한다. 스킬·플러그인의 데스크톱 UI 제외 규칙을 README 디자인 제외로 해석하지 않는다. 사용자가 텍스트 전용 등 다른 형식을 명시하면 그 요구가 우선한다.
- 제목과 항목 순서를 맞추는 것만으로 완료하지 않는다. 실제로 표시되는 **프로젝트 전용 상단 커버**, 짧은 제목·소개, **설치·다운로드를 강조한 링크형 버튼**, 핵심 기능을 비교하기 쉬운 표나 시각적 묶음, **기능을 보여주는 시각 자료**를 구성한다. 확인 가능한 배지를 짧은 줄로 배치하되 근거 없는 배지는 만들지 않는다. 하단 홈페이지 배지 하나만으로 디자인을 충족했다고 판단하지 않는다.
- 화면이 없는 스킬·플러그인은 실제 결과물 예시, 입력→처리→결과 도식 또는 사용 흐름 SVG로 기능을 보여준다. 가상의 앱 화면을 만들거나 없는 기능을 표현하지 않는다. 표·도식에 들어갈 설명도 실제 사용자가 얻는 결과 중심으로 쓴다.
- 커버의 글자 크기 차이·여백·기능별 그래픽과 본문의 제목 계층·구분선·간격을 일관되게 설계한다. 템플릿의 중앙 정렬 상단과 짧은 배지 줄을 유지하되 모든 프로젝트에 같은 소재를 복사하지 않는다. 이미지 생성이 없어도 실제 폰트와 벡터 도형으로 SVG 커버·도식을 구현할 수 있다.
- 첫 화면에 긴 내부 구조 설명·개발 단계명·명령 목록을 쌓지 않는다. 상세 기술·전체 명령·시험 절차는 별도 문서나 접는 영역으로 옮기되 필수 실행 조건·기능 제한·라이선스는 찾기 쉽게 유지한다.
- 게시 전 GitHub용 렌더링 화면을 직접 확인하여 커버와 시각 자료가 실제 보이고, 버튼이 눈에 띄며, 긴 설명이 첫 화면을 압도하지 않는지 검수한다. 문법 검사나 이미지 경로 확인만으로 시각 검증을 대신하지 않는다. 도구 제한으로 화면을 확인하지 못하면 시각 검증 미완료를 명시한다. 기존 디자인은 작은 문구 수정·재배포만으로 제거하거나 전면 개편하지 않는다.

### 구성과 내용

- 대상 프로젝트의 GitHub README를 새로 만들거나 첫 페이지 개편을 요청받으면 아래 구성을 기본으로 한다. 기존 앱의 작은 기능 수정만으로 README 전체를 개편하지 않는다.
- [Contentrium Dev Skill 첫 페이지](https://github.com/contentriumkorea/contentrium-dev-skill)는 시각적 위계와 정보 배치의 참고다. 이 문서의 기준만으로도 구현할 수 있어야 하며, 참고 페이지를 매번 열거나 외부 저장소의 로고·문구·성과 수치를 복사할 필요는 없다.
- 상단은 **프로젝트 전용 커버 → 이름과 한두 문장의 소개 → 필요한 배지와 설치·다운로드 바로가기** 순으로 간결하게 구성한다. 이어 **핵심 기능 → 실제 화면·사용 예시 또는 명확히 표시한 시안 → 짧은 설치·사용 방법**을 배치한다. 긴 설치 안내·문제 해결·개발 자료는 별도 문서 또는 접을 수 있는 영역으로 분리한다.
- 커버의 소재·색감·구도와 소개 문구는 프로그램의 핵심 기능, 사용 목적, 사용자에게 주는 이점을 반영해 각각 제작한다. 동일한 배경이나 이름만 바꾼 커버를 모든 프로그램에 재사용하지 않는다. Contentrium Dev Skill의 무채색 커버와 BUILD·LAUNCH·RELEASE 문구도 고정 템플릿이 아니다. 별도 브랜드 지침이 있으면 우선한다.
- 커버는 읽기 쉬운 타이포그래피와 여백을 중심으로 제작한다. SVG 등으로 텍스트를 직접 구현할 수 있으며, 생성 이미지를 사용하면 배경 소재에만 사용하고 제목·설명은 실제 폰트로 별도 조합한다. README 본문에도 프로그램명과 설명을 텍스트로 제공하고 이미지에는 대체 텍스트를 넣는다.
- 기능은 실제 제공하는 내용만 간결하게 설명한다. 배지는 확인 가능한 버전·지원 환경·라이선스 등 필요한 항목만 사용한다. 검증되지 않은 호환성·성능·다운로드 수를 꾸며 넣지 않고, 디자인 시안을 실제 제품 화면으로 소개하지 않는다.
- GitHub에서 표시 가능한 Markdown·HTML과 저장소 이미지로 구성하고 실행 스크립트나 사용자 정의 CSS에 의존하지 않는다. 게시 전 렌더링, 좁은 화면의 가독성, 이미지 경로와 링크를 확인하고 게시 후 공개된 파일과 다운로드 연결을 검증한다.
- README 상단에 프로젝트 유형에 맞는 설치·다운로드 진입점과 간단한 설치 방법을 배치한다. 신규 데스크톱 앱은 경량 설치기와 포터블로, 스킬·플러그인은 실제 지원하는 설치 명령·플랫폼 등록 페이지·패키지로 연결한다. 기존 프로젝트의 승인된 설치 구조를 유지하고 최신 정식 배포에 유효한 링크인지 확인한다.
- 프로그램 소개·README·릴리스 설명은 목적, 주요 기능, 설치·사용 방법, 사용자에게 영향을 주는 변경 사항 중심으로 쓴다.

## 데스크톱 앱의 세 가지 배포 구성

신규 데스크톱 앱의 기본 배포 구성이다. 사용자가 다른 구성을 명시하면 그 요구를 따르고, 기존 앱의 일부 수정에 새 배포 유형을 소급 추가하지 않는다. 스킬·플러그인 패키지 자체에는 적용하지 않는다.

| 구성 | 역할 |
| --- | --- |
| 경량 설치기 | 사용자가 실행하면 최신 정식 릴리스를 확인하고 설치용 패키지를 내려받아 설치하는 진입 파일 |
| 최신 정식 프로그램 패키지 | 경량 설치기가 실제로 내려받는 해당 버전의 설치용 본체. 릴리스 자산 및 필요한 매니페스트와 연결 |
| 포터블 ZIP | 설치 없이 압축을 풀고 실행할 수 있는 독립 실행 패키지 |

- 최신 정식 릴리스에 세 구성을 함께 제공한다. 경량 설치기는 별도 파일이며 최신 본체 패키지의 전체 내용을 내장하지 않는다. 최신 릴리스라는 페이지 이름만으로 설치용 본체를 대신하지 않는다.
- 설치기가 참조하는 OS·아키텍처별 자산과 무결성 정보를 명확히 연결한다. 설치형 본체와 포터블 앱은 같은 정식 앱 버전이어야 한다. 설치기 자체 버전은 별도로 관리할 수 있다.
- README 상단에 **설치형 다운로드**와 **포터블 ZIP 다운로드**를 구분한다. 설치형 링크는 경량 설치기로, 포터블 링크는 압축 해제 후 바로 실행할 수 있는 ZIP으로 연결한다.
- 포터블 ZIP에 설치기만 넣거나 소스 코드 ZIP을 포터블이라고 부르지 않는다. 실행 파일과 필요한 런타임·자산을 포함하고 별도 설치·관리자 권한·설치본 의존 없이 실행되는지 확인한다. 기능상 이 조건을 충족할 수 없으면 원인을 설명하고 포터블 제공 완료로 보고하지 않는다.
- 포터블 실행만으로 설치용 바로가기·서비스·제거 프로그램·자동 실행 등 영구적인 시스템 등록을 수행하지 않는다. 실행 중 작업표시줄과 트레이 UI는 앱 기능에 맞게 사용할 수 있다. 휴대할 설정과 데이터의 저장 위치를 명확히 안내한다.
- 배포 검증 시 설치기 → 최신 정식 본체 다운로드 → 설치 → 실행 경로와, 포터블 ZIP → 새 폴더 압축 해제 → 직접 실행 경로를 각각 확인한다.

## 공개 전후 확인

- 업로드 대상, 압축파일 내용, 빌드 결과 및 함께 공개되는 이력에서 비밀키·토큰·개인정보·비공개 자료가 제외되었는지 확인한다. 실제 비밀값을 출력하지 않는다.
- 설치기·패키지·매니페스트 등 자동 설치에 필요한 자산 이름은 안정적으로 유지한다. 일반 납품용 ZIP의 날짜 규칙과 구분한다.
- 배포 후 의도한 공개 상태, 릴리스 자산, README 다운로드 링크와 실제 다운로드 가능 여부를 확인한다. 비공개 배포는 의도한 권한으로 확인한다.
- 실제 확인한 URL과 검증 결과를 보고한다. 업로드 성공만으로 설치 성공을 주장하지 않는다.

## 최신 릴리스만 공개 유지

- 승인된 배포 대상의 동일 제품·동일 배포 채널에서 최신 정식 릴리스만 공개하고 이전 버전은 초안(Draft)으로 보관한다. 복합 저장소의 다른 제품, 별도 지원 버전·채널, 시험판 및 관계없는 저장소는 변경하지 않는다. 사용자가 지정한 유지 정책을 우선하며 제품·채널 구분이 불명확하면 초안 전환을 보류한다.
- 게시 전에 이전 정상 버전과 다운로드 진입점을 기록한다. 새 정식 릴리스를 게시하고 해당 제품·채널의 다운로드 연결, 무결성 및 필요한 설치·패키지 동작을 검증한다. 저장소의 Latest 및 공용 latest URL은 다른 제품·채널에 영향을 주지 않는 경우에만 사용하고, 복합 저장소는 제품·채널별 진입점을 유지한다.
- 새 버전 검증에 실패하면 이전 정상 버전으로 다운로드 진입점과 변경한 Latest 지정을 복구하고, 실패한 새 릴리스는 초안으로 전환한 뒤 복구 결과를 확인한다. 첫 배포라 이전 버전이 없으면 실패 릴리스를 초안으로 전환하고 정상 배포가 없음을 알린다. 권한·설정 때문에 복구할 수 없으면 반복 변경을 멈추고 현재 상태와 제한을 보고한다.
- 이전 릴리스를 숨기기 전 새 설치기뿐 아니라 이미 배포한 설치기·업데이터·패키지 관리자·문서의 지원 중인 다운로드 경로가 그 자산에 의존하는지 확인한다. 자산을 최신 릴리스로 복사하는 것만으로 기존의 고정 URL이 복구된다고 판단하지 않는다. 연결을 보존할 수 없거나 의존성이 불명확하면 해당 이전 릴리스는 공개로 유지하고 이유를 보고한다. 기존 사용자 연결 보호가 최신 하나만 공개하는 기본값보다 우선한다.
- 새 버전 검증과 의존성 확인이 끝나면 페이지 누락 없이 릴리스 목록을 조회하고, 같은 제품·채널의 이전 공개 정식 릴리스만 초안으로 전환한다. 이미 초안인 릴리스는 유지하며 생성일만으로 최신 정식 버전을 판단하지 않는다.
- 릴리스·첨부파일·태그·커밋을 삭제하지 않는다. 초안 전환은 이전 배포 자료를 공개 릴리스에서 숨기는 것이며 공개 저장소의 과거 소스 이력을 비공개로 만들지는 않는다.
- 전환 후 인증된 조회에서 대상 이전 버전의 초안 상태를 확인하고, 공개 배포는 비인증 조회로 최신 버전과 실제 다운로드를 확인한다. 비공개 배포는 의도한 권한으로 확인한다. 다른 제품·채널의 릴리스는 유지되었는지 확인하고, 전환이 막히면 삭제로 대체하지 않는다.
